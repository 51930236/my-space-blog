# 修复记录

## hexo-theme-redefine 文章加密功能修复

### 问题描述

文章设置 `password: 123456` 后，页面输入密码无响应，控制台报错：

```
Uncaught ReferenceError: log is not defined at hello-world/:1:23332
[DOM] Password field is not contained in a form
```

### 根因分析

hexo-theme-redefine 的加密功能基于 hexo-blog-encrypt 实现，加密流程分为两步：

1. **构建时**（Node.js）：`scripts/filters/encrypt.js` 在 `after_post_render` 阶段加密文章内容，并注入 HBE 模板和内联脚本
2. **运行时**（浏览器）：`source/js/plugins/hbe.js` 的 `initHBE()` 函数绑定密码输入框事件，处理解密逻辑

**问题 1：`log is not defined`**

`encrypt.js` 第 128 行注入的内联脚本包含：

```javascript
log.info(ensurePrefix("hexo-blog-encrypt: loaded."));
```

- `log` 是 Node.js 端 `hexo.log` 的引用，在浏览器中不存在
- `ensurePrefix` 是 CommonJS 模块 `log-prefix.js` 导出，也不存在于浏览器环境
- 该错误导致整个 `<script type="module">` 执行中断，`initHBE()` 未被调用，密码输入框没有事件监听

**问题 2：`Password field is not contained in a form`**

HBE 模板（`hbe.default.js`）中的密码输入框 `<input type="password">` 未包裹在 `<form>` 元素中，违反 HTML 规范，浏览器发出警告。

### 修改文件

#### 1. `scripts/filters/encrypt.js` — 修复 `log is not defined`

**改动**：移除内联脚本中的 `log.info(ensurePrefix(...))` 调用，直接调用 `initHBE()`

```diff
 <script data-swup-reload-script type="module">
 import {initHBE} from "${hexo.config.root}js/plugins/hbe.js";
-  log.info(ensurePrefix("hexo-blog-encrypt: loaded."));
-    initHBE();
+  initHBE();
 </script>
```

#### 2. `scripts/filters/lib/hbe.default.js` — 修复 `Password field is not contained in a form`

**改动**：在密码输入框外层包裹 `<form onsubmit="return false;">`

```diff
 <div class="hbe hbe-input hbe-input-default">
+  <form onsubmit="return false;">
     <input class="hbe hbe-input-field hbe-input-field-default" type="password" id="hbePass">
     <label class="hbe hbe-input-label hbe-input-label-default" for="hbePass">
       <span class="hbe hbe-input-label-content hbe-input-label-content-default">{{hbeMessage}}</span>
     </label>
+  </form>
 </div>
```

### 验证方式

```bash
npx hexo clean && npx hexo generate
```

检查生成的 `public/2026/08/07/hello-world/index.html` 中：
- 内联脚本仅包含 `import{initHBE}from"/js/plugins/hbe.js";initHBE()`
- 密码输入框被 `<form>` 包裹

然后启动 `hexo server` 访问加密文章，输入密码 123456 验证解密是否正常。

## CI/CD 持久化：使用 patch-package 让补丁在 GitHub Actions 中生效

### 问题

以上修改直接改了 `node_modules/hexo-theme-redefine`，是 npm 依赖内容。GitHub Actions 执行 `npm ci` 时会从 registry 重新安装未修改的版本，导致构建出来的站点仍然有 Bug。

### 解决方案

使用 `patch-package` 工具，将补丁文件纳入版本控制，`npm install` / `npm ci` 后自动应用。

### 操作方法

1. 安装 `patch-package`

```bash
npm install --save-dev patch-package
```

2. 生成补丁文件（已执行）

```bash
npx patch-package hexo-theme-redefine
```

生成文件：`patches/hexo-theme-redefine+2.9.0.patch`，包含所有 3 处修改的 diff。

3. 配置 `postinstall` 钩子（已执行）

在 `package.json` 中添加：

```json
"scripts": {
  "postinstall": "patch-package"
}
```

4. 提交版本控制

需要提交的文件：
- `patches/hexo-theme-redefine+2.9.0.patch` — 补丁文件
- `package.json` — postinstall 脚本
- `package-lock.json` — patch-package 依赖锁定

### 原理

- `npm ci` / `npm install` 完成后会自动执行 `postinstall` 脚本
- `patch-package` 会读取 `patches/` 目录下的 `.patch` 文件，将 diff 应用到对应的 `node_modules` 包中
- 本地和 CI/CD 环境都能生效，无需手动维护
