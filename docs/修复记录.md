# 修复记录

## hexo-theme-redefine 文章加密功能修复

### 问题描述

文章设置 `password: 123456` 后，页面输入密码无响应，控制台报错：

```
Uncaught ReferenceError: log is not defined at hello-world/:1:23332
[DOM] Password field is not contained in a form
```

### 根因分析

hexo-theme-redefine 的加密功能基于 hexo-blog-encrypt 实现，加密流程分为两步：

1. **构建时**（Node.js）：`scripts/filters/encrypt.js` 在 `after_post_render` 阶段加密文章内容，并注入 HBE 模板和内联脚本
2. **运行时**（浏览器）：`source/js/plugins/hbe.js` 的 `initHBE()` 函数绑定密码输入框事件，处理解密逻辑

**问题 1：`log is not defined`**

`encrypt.js` 第 128 行注入的内联脚本包含：

```javascript
log.info(ensurePrefix("hexo-blog-encrypt: loaded."));
```

- `log` 是 Node.js 端 `hexo.log` 的引用，在浏览器中不存在
- `ensurePrefix` 是 CommonJS 模块 `log-prefix.js` 导出，也不存在于浏览器环境
- 该错误导致整个 `<script type="module">` 执行中断，`initHBE()` 未被调用，密码输入框没有事件监听

**问题 2：`Password field is not contained in a form`**

HBE 模板（`hbe.default.js`）中的密码输入框 `<input type="password">` 未包裹在 `<form>` 元素中，违反 HTML 规范，浏览器发出警告。

### 修改文件

#### 1. `scripts/filters/encrypt.js` — 修复 `log is not defined`

**改动**：移除内联脚本中的 `log.info(ensurePrefix(...))` 调用，直接调用 `initHBE()`

```diff
 <script data-swup-reload-script type="module">
 import {initHBE} from "${hexo.config.root}js/plugins/hbe.js";
-  log.info(ensurePrefix("hexo-blog-encrypt: loaded."));
-    initHBE();
+  initHBE();
 </script>
```

#### 2. `scripts/filters/lib/hbe.default.js` — 修复 `Password field is not contained in a form`

**改动**：在密码输入框外层包裹 `<form onsubmit="return false;">`

```diff
 <div class="hbe hbe-input hbe-input-default">
+  <form onsubmit="return false;">
     <input class="hbe hbe-input-field hbe-input-field-default" type="password" id="hbePass">
     <label class="hbe hbe-input-label hbe-input-label-default" for="hbePass">
       <span class="hbe hbe-input-label-content hbe-input-label-content-default">{{hbeMessage}}</span>
     </label>
+  </form>
 </div>
```

### 验证方式

```bash
npx hexo clean && npx hexo generate
```

检查生成的 `public/2026/08/07/hello-world/index.html` 中：
- 内联脚本仅包含 `import{initHBE}from"/js/plugins/hbe.js";initHBE()`
- 密码输入框被 `<form>` 包裹

然后启动 `hexo server` 访问加密文章，输入密码 123456 验证解密是否正常。

## 功能：加密文章解密后显示目录（TOC）

### 需求

加密文章在输入密码解锁文章内容后，应该显示隐藏目录图标，并支持目录滚动高亮功能。

### 根因分析

`toc.ejs` 使用 `page.content` 通过 `hexo.toc()` 生成目录 HTML。加密文章的内容被替换为加密模板（密码输入框等），其中不包含文章标题，导致 `toc()` 生成空目录。`toc.js` 检测到 `navItems.length === 0` 后移除目录容器和切换按钮。

解密后即使 `redefine:page:refresh` 事件重新触发了 `initTOC()`，但目录容器已被移除，无法恢复。

#### `layout/pages/post/toc.ejs` — 加密文章使用原始内容生成目录

### 原理

- 构建时：`encrypt.js` 在加密前将 `data.content` 保存到 `data.origin`（第 75 行）
- 构建时：`toc.ejs` 判断 `page.encrypt`，加密文章从 `page.origin` 生成目录，正常文章仍用 `page.content`
- 构建时：`encrypt.js` 在加密内容最前面注入 `<style>` 带 `!important`，尝试隐藏目录

- 解密后：`hbe.js` 移除 CSS `<style>` 元素 + 用 `removeProperty("display")` 移除 JS 内联样式，然后触发 `redefine:page:refresh`，`main.js` 重新调用 `initTOC()` 绑定滚动高亮

## CI/CD 持久化：使用 patch-package 让补丁在 GitHub Actions 中生效

### 问题

以上修改直接改了 `node_modules/hexo-theme-redefine`，是 npm 依赖内容。GitHub Actions 执行 `npm ci` 时会从 registry 重新安装未修改的版本，导致构建出来的站点仍然有 Bug。

### 解决方案

使用 `patch-package` 工具，将补丁文件纳入版本控制，`npm install` / `npm ci` 后自动应用。

### 操作方法

1. 安装 `patch-package`

```bash
npm install --save-dev patch-package
```

2. 生成补丁文件（已执行）

```bash
npx patch-package hexo-theme-redefine
```

生成文件：`patches/hexo-theme-redefine+2.9.0.patch`，包含所有 3 处修改的 diff。

3. 配置 `postinstall` 钩子（已执行）

在 `package.json` 中添加：

```json
"scripts": {
  "postinstall": "patch-package"
}
```

4. 提交版本控制

需要提交的文件：
- `patches/hexo-theme-redefine+2.9.0.patch` — 补丁文件
- `package.json` — postinstall 脚本
- `package-lock.json` — patch-package 依赖锁定

### 原理

- `npm ci` / `npm install` 完成后会自动执行 `postinstall` 脚本
- `patch-package` 会读取 `patches/` 目录下的 `.patch` 文件，将 diff 应用到对应的 `node_modules` 包中
- 本地和 CI/CD 环境都能生效，无需手动维护

## 新增功能：home_banner 单图自定义染色模式

### 需求

在原有的 `light` / `dark` 双图模式基础上，新增一个 `custom_style` 选项，开启后只使用一张背景图，暗色模式时通过 CSS filter + mix-blend-mode 渐变染色层自动转换色调。

### 配置

`_config.redefine.yml` 新增：

```yaml
home_banner:
  image:
    light: /images/xxx-light.webp # 背景图
    dark: /images/xxx-dark.webp   # 暗色模式图（custom_style: false 时使用）
    custom_style: false           # 自定义单图模式，暗色模式自动染色
```

- `custom_style: false`（默认）— 保持原行为，亮色用 `light`，暗色用 `dark`
- `custom_style: true` — 只用 `light` 一张图，暗色模式自动染色

### 原理

参考 `doubao_html_20260811_230016.html` 的实现：

1. **CSS filter**：暗色模式下对图片应用 `brightness(0.72) contrast(1.15) saturate(0.85)`，压暗图片
2. **渐变染色层**：一个绝对定位的 `div.night-overlay`，使用 `mix-blend-mode: color` 叠加在图片上，通过 `linear-gradient` 按天空/山腰/湖面区域染色
3. 动画过渡：`transition: opacity 0.7s ease` 实现明暗切换的平滑过渡

### 修改文件

#### `_config.redefine.yml` — 新增配置项

```diff
   image:
     light: /images/wallhaven-wqery6-light.webp
     dark: /images/wallhaven-wqery6-dark.webp
+    custom_style: false # 新增
```

#### `layout/pages/home/home-banner.ejs` — 条件渲染

```diff

- <img src="dark" class="hidden dark:block">
+ <% if (custom_style) { %>
+   <img src="light" class="dark:brightness-[0.72] dark:contrast-[1.15] dark:saturate-[0.85]">
+   <div class="night-overlay"></div>
+ <% } else { %>
+   <!-- 原双图模式 -->
+ <% } %>
```

同时新增 `.night-overlay` CSS 样式（包含渐变背景、`mix-blend-mode: color`、暗色模式 `opacity: 0.6` 等）。

#### `layout/pages/home/home-background.ejs` — 同上条件渲染

### 使用方式

将 `custom_style` 改为 `true` 即可体验单图自动染色效果。如使用其他图片，可调整 `linear-gradient` 的色值以匹配图片色调。

## 新增功能：home_banner 幻灯片轮播背景图

### 需求

在 `custom_style: true` 的基础上，支持定时切换背景图列表，可配置切换间隔和图片列表。

### 配置

`_config.redefine.yml` 新增 `slideshow` 配置项：

```yaml
home_banner:
  image:
    light: /images/xxx-light.webp
    dark: /images/xxx-dark.webp
    custom_style: true
    slideshow:
      enable: false       # 是否启用定时切换
      interval: 10        # 切换间隔（秒）
      list: []            # 背景图列表
```

### 优先级

- `custom_style: false` → 双图模式（`light` + `dark`）
- `custom_style: true` + `slideshow.enable: false` → 单图染色模式（使用 `light`）
- `custom_style: true` + `slideshow.enable: true` → 幻灯片轮播模式（使用 `list`）

### 原理

1. 所有图片以绝对定位堆叠在 `.home-banner-background` 容器内
2. 通过 `.slideshow-img.active` 控制 `opacity` 显示当前图片，`1s` 过渡动画
3. 内联 `setInterval` 定时器按配置间隔轮播，`data-interval` 属性传递间隔值
4. `data-swup-reload-script` 确保 Swup 页面切换时脚本重新执行

### 修改文件

#### `_config.redefine.yml` — 新增配置项


#### `layout/pages/home/home-banner.ejs`
